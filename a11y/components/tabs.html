Tabs

Tabs are a set of controls that display one associated panel of content at a time. Selecting a tab hides the previously displayed panel and displays the panel associated with the selected tab.

Tabs differ from other controls:

  • Use tabs when users need to switch between closely related, layered sections of content without leaving the current page or context.
  • Use an accordion when users may need to view multiple sections at the same time, particularly in a vertically stacked layout.
  • Use a disclosure when a single control shows or hides related content.
  • Use navigation links when activation takes users to separate pages or locations.
  • Use a radio group when users select a value rather than choose which content panel is visible.
  • Do not use tabs merely as visual styling for buttons, links, filters, or a step-by-step process with different interaction requirements.

WCAG requirements

  • The tab container exposes role="tablist". (4.1.2)
  • Each tab exposes role="tab". (4.1.2)
  • Each tab panel exposes role="tabpanel". (4.1.2)
  • The tablist has a programmatically determinable accessible name when its purpose is not otherwise clear from surrounding structure or context. (1.3.1, 2.4.6, 4.1.2)
  • Each tab has a programmatically determinable accessible name that identifies the associated panel or topic. (2.4.6, 4.1.2)
  • The selected tab exposes aria-selected="true", and unselected tabs expose aria-selected="false". (4.1.2)
  • Each tab identifies its associated panel with aria-controls set to the id of the corresponding tab panel. (1.3.1, 4.1.2)
  • Each tab panel is associated with its tab, such as by using aria-labelledby set to the id of the corresponding tab. (1.3.1, 4.1.2)
  • Only the selected tab panel is visible and available for interaction in a single-select tab interface. Unselected panels are hidden and do not contain reachable keyboard-focus targets. (1.3.1, 2.1.1, 2.4.3, 4.1.2)
  • The tablist and tabs are operable with a keyboard. (2.1.1)
  • Only one tab in a single-select tablist is in the normal Tab sequence. The currently selected tab is normally the tab stop, and inactive tabs are reached with arrow keys. (2.1.1, 2.4.3)
  • The focused tab has a visible focus indicator. (2.4.7)
  • Focused tabs are not completely hidden by sticky headers, banners, dialogs, or other author-created content. (2.4.11)
  • The selected state is not conveyed by color alone. (1.4.1)
  • Tab labels, selected-state indicators, and focus indicators have sufficient contrast. (1.4.3, 1.4.11)
  • The tablist and tab panels remain usable when text is enlarged, spacing is increased, or the viewport is narrow. (1.4.4, 1.4.10, 1.4.12)
  • Tabs meet the minimum target-size requirement or an applicable exception applies. (2.5.8)
  • Selecting, focusing, or activating a tab does not unexpectedly submit a form, open a dialog, navigate to a different page, or otherwise cause an unexpected change of context. (3.2.1, 3.2.2)

Manual-activation tabs

In a manual-activation tab interface, moving focus between tabs does not immediately change the displayed panel. Users press Enter or Space to activate the focused tab.

  • The focused tab can be distinguished from the selected tab visually. (1.4.1, 1.4.11, 2.4.7)
  • Moving focus with arrow keys does not change the selected tab or displayed panel. (2.4.3, 3.2.1)
  • Pressing Enter or Space on a focused tab selects it and displays its associated panel. (2.1.1, 4.1.2)
  • The selected state and visible panel update when the user activates a tab. (1.3.1, 4.1.2)

Automatic-activation tabs

In an automatic-activation tab interface, moving focus to a tab also selects it and displays its associated panel.

  • Moving focus to a tab updates the selected state and displayed panel without perceptible delay. (2.1.1, 2.4.3, 4.1.2)
  • Arrow-key navigation does not cause an unexpected change of context. (3.2.1)
  • The selected state and visible panel update each time focus moves to a new tab. (1.3.1, 4.1.2)
  • The user can move quickly through tabs without waiting for panels to load or render. (2.1.1)

Best practices

These practices improve usability and robustness, although not all are separate WCAG requirements in every implementation.

  • Use the complete tab pattern only when the controls actually select associated content panels.
  • Use concise tab labels that identify the topic of each panel, such as Overview, Specifications, and Reviews.
  • Keep the number of tabs manageable. When there are many options, consider a different pattern such as navigation, a select element, or an accordion.
  • Use automatic activation only when each panel can display without perceptible delay. Use manual activation when loading or rendering panel content may be delayed.
  • For manual activation, provide an understandable indication of the focused tab separate from the selected tab.
  • Keep the selected tab visually distinct using more than color, such as an underline, border, indicator shape, font treatment, or associated visible panel.
  • Use horizontal tabs by default. For vertical tabs, expose aria-orientation="vertical" on the tablist.
  • Keep tab labels and their associated panels in a stable order.
  • Do not automatically move keyboard focus into the tab panel when a tab is selected.
  • Ensure that panel content begins with a meaningful heading when a visible heading is appropriate.
  • When a tab panel contains significant content, make sure the panel is easy to reach after navigating the tablist.
  • Do not place interactive controls or links inside a tab label unless the implementation follows a specialized pattern that handles their separate keyboard interactions.
  • Do not use tabs for a linear multistep process where users must complete steps in sequence. Use an appropriate stepper or workflow pattern instead.
  • Consider showing all tab panels in print styles so that users can print the complete content.

Practical test sequence

Focus Details Applicable Criteria
Identify function
  • Confirm that the controls are tabs: they select associated content panels in the same interface rather than navigating to separate pages, filtering a list, or selecting form values. (1.3.1, 4.1.2)
  • Confirm that only one panel is intended to be displayed at a time, unless the component is intentionally a multi-select tab interface.
  • Determine whether the tab interface uses automatic or manual activation.
  • Determine whether the tablist is horizontal or vertical.
  • WCAG 2.2: Understanding SC 1.3.1 Info and Relationships (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Semantics and language
  • Confirm the tab container exposes role="tablist". (4.1.2)
  • Confirm each tab exposes role="tab" and each panel exposes role="tabpanel". (4.1.2)
  • Confirm each tab has a meaningful accessible name that identifies its associated panel. (2.4.6, 4.1.2)
  • Confirm that the tablist has an accessible name when its purpose is not otherwise clear from visible context or heading structure. (1.3.1, 2.4.6, 4.1.2)
  • Confirm each tab has aria-controls set to the id of its associated panel. (1.3.1, 4.1.2)
  • Confirm each panel has aria-labelledby set to the id of its associated tab. (1.3.1, 4.1.2)
  • Confirm that the selected tab has aria-selected="true" and other tabs have aria-selected="false". (4.1.2)
  • For a vertical tablist, confirm that aria-orientation="vertical" is exposed. (4.1.2)

  • WCAG 2.2: Understanding SC 2.4.6 Headings and Labels (Level AA)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Screen reader
  • Confirm that the tablist is identified as a tablist and that each control is announced as a tab. (4.1.2)
  • Verify that each tab has a meaningful accessible name. (4.1.2)
  • Verify that the selected or unselected state is announced when each tab receives focus. (4.1.2)
  • Confirm that the relationship between each tab and its associated panel is available programmatically. (1.3.1, 4.1.2)
  • Activate each tab and confirm that the correct panel is available and identified as a tab panel. (1.3.1, 4.1.2)
  • Confirm that unselected panels are not presented as currently available content and do not contain reachable controls. (1.3.1, 2.1.1, 4.1.2)
  • For a manual-activation interface, confirm that moving focus alone does not announce an incorrect selected state or expose the wrong panel. (4.1.2)
  • For an automatic-activation interface, confirm that the selected state and panel content update when focus moves to a tab. (4.1.2)
  • WCAG 2.2: Understanding SC 1.3.1 Info and Relationships (Level A)
  • WCAG 2.2: Understanding SC 2.1.1 Keyboard (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Keyboard only
  • Use Tab and Shift+Tab to move into and out of the tablist. Confirm that only one tab in a single-select tablist is reached with Tab. (2.1.1, 2.4.3)
  • For horizontal tabs, use Right Arrow and Left Arrow to move focus between tabs. Confirm that focus wraps from the last tab to the first and from the first tab to the last. (2.1.1)
  • For vertical tabs, use Down Arrow and Up Arrow to move focus between tabs. Confirm that focus wraps from the last tab to the first and from the first tab to the last. (2.1.1)
  • Use Home to move focus to the first tab and End to move focus to the last tab, when these optional commands are implemented. (2.1.1)
  • For manual-activation tabs, use Enter and Space to select the focused tab and display its panel. (2.1.1)
  • For automatic-activation tabs, confirm that moving focus to a tab selects it and displays its panel without perceptible delay. (2.1.1, 2.4.3)
  • Confirm that the focused tab has a visible focus indicator and is not completely hidden by other content. (2.4.7, 2.4.11)
  • Confirm that the tablist does not create a keyboard trap and that focus moves logically from the active tab to panel content and then to the next page control. (2.1.2, 2.4.3)
  • Confirm that selecting or focusing a tab does not unexpectedly navigate away, submit a form, move focus into the panel, or cause another unexpected change of context. (2.4.3, 3.2.1, 3.2.2)

  • WCAG 2.2: Understanding SC 2.1.2 No Keyboard Trap (Level A)
  • WCAG 2.2: Understanding SC 2.4.3 Focus Order (Level A)
  • WCAG 2.2: Understanding SC 2.4.7 Focus Visible (Level AA)
  • WCAG 2.2: Understanding SC 2.4.11 Focus Not Obscured (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 3.2.1 On Focus (Level A)
  • WCAG 2.2: Understanding SC 3.2.2 On Input (Level A)
Panels and content
  • Activate each tab and confirm that its associated panel is displayed while unselected panels are hidden. (1.3.1, 4.1.2)
  • Confirm that hidden panels do not contain keyboard-focusable elements that can be reached while the panel is inactive. (2.1.1, 2.4.3)
  • Confirm that the displayed panel's content appears in a meaningful reading order. (1.3.2)
  • Confirm that interactive controls in the displayed panel are reachable with the keyboard in a logical order. (2.1.1, 2.4.3)
  • Confirm that the displayed panel remains identifiable when users enter it from the keyboard or screen-reader reading order. (1.3.1, 2.4.6)
  • If a panel loads content dynamically, confirm that loading, errors, and completion status are communicated where appropriate. (4.1.2, 4.1.3)

Inspect visual aspects
  • Check contrast for tab labels, selected-state indicators, icons, and focus indicators. (1.4.3, 1.4.11)
  • Confirm that selected and unselected states are not distinguished by color alone. (1.4.1)
  • For manual-activation tabs, confirm that focused and selected states are visually distinguishable from one another. (1.4.1, 1.4.11)
  • Check 200% text resize, a 320-CSS-pixel-wide viewport, and text-spacing overrides. Tab labels, tab controls, and panel content must remain visible, usable, and unclipped. (1.4.4, 1.4.10, 1.4.12)
  • Confirm that horizontal tabs provide a usable responsive treatment when there is insufficient width, without requiring inappropriate two-dimensional page scrolling. (1.4.10)
  • Confirm that each tab meets the minimum target size or has sufficient spacing from adjacent targets. (2.5.8)
  • Confirm that the focus indicator is visible against surrounding colors and is not completely hidden by other content. (1.4.11, 2.4.11)
