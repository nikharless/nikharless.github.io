Breadcrumbs

A breadcrumb trail is a secondary navigation pattern that shows a user's location within a website or application hierarchy. It typically contains links to ancestor pages followed by the current page.

Breadcrumbs differ from other navigation patterns:

  • Use breadcrumbs to show hierarchical location and provide links back to parent pages or sections.
  • Use primary navigation for major site sections and primary routes.
  • Use a back link or browser back behavior when users need to return to the page they visited immediately before the current page.
  • Use pagination to move among sequential pages within a collection.
  • Do not use breadcrumbs as the only way to navigate a site or application.
  • Do not use breadcrumbs to reproduce a user's exact browsing history unless the product intentionally provides history-based navigation.

WCAG requirements

  • Each breadcrumb link has a programmatically determinable accessible name. (4.1.2)
  • The purpose of each breadcrumb link can be determined from its text alone or from its text together with programmatically determinable context. (2.4.4)
  • Breadcrumb links expose link semantics. A native <a> element with an href provides link semantics automatically. (4.1.2)
  • Breadcrumb links are operable using a keyboard. A native link can be activated with Enter. (2.1.1)
  • Breadcrumb links appear in a logical focus order that follows the displayed hierarchy. (2.4.3)
  • Breadcrumb links have a visible focus indicator when they receive keyboard focus. (2.4.7)
  • Focused breadcrumb links are not completely hidden by sticky headers, banners, dialogs, or other author-created content. (2.4.11)
  • Breadcrumb links are visually distinguishable from surrounding non-link text without relying on color alone. (1.4.1)
  • Breadcrumb-link text has sufficient contrast against its background. (1.4.3)
  • Link indicators, separators needed to understand the hierarchy, and focus indicators have sufficient non-text contrast where required. (1.4.11)
  • Visible breadcrumb-link text is included in the accessible name. (2.5.3)
  • Breadcrumbs remain visible, identifiable, and operable at 200% text resize, at a 320-CSS-pixel-wide viewport, and when text-spacing overrides are applied. (1.4.4, 1.4.10, 1.4.12)
  • Standalone breadcrumb links meet the minimum target-size requirement or an applicable exception applies. Inline breadcrumb links whose size is constrained by the line height of non-target text may qualify for the inline exception. (2.5.8)
  • If the current page is included as a link, it is programmatically identified as the current page with aria-current="page". (1.3.1, 4.1.2)
  • When visual separators between breadcrumb items are decorative, they are not exposed to assistive technology. If a separator conveys information beyond ordinary hierarchy, its meaning is available programmatically or in text. (1.1.1, 1.3.1)
  • If the current page is presented as non-link text, it is distinguishable from the linked breadcrumb items. (1.3.1, 1.4.1)
  • When breadcrumb navigation is repeated across multiple pages within a set of pages, it occurs in the same relative order each time it is repeated. (3.2.3)
  • Breadcrumb labels, destinations, and current-page treatment are identified consistently when the same pattern appears across multiple pages. (3.2.4)
  • Breadcrumb links do not cause an unexpected change of context when they receive focus. (3.2.1)

Hierarchical breadcrumbs

Hierarchical breadcrumbs show the current page's location within the site or application structure. This is the most common breadcrumb pattern.

  • The breadcrumb sequence accurately reflects the hierarchy from ancestor page or section to current page. (1.3.1)
  • Each ancestor item links to the correct parent page or section. (2.4.4)
  • The current page is represented as the final item when included. (1.3.1)
  • If the current page is a link, it exposes aria-current="page". (4.1.2)

Location breadcrumbs without current-page link

Some breadcrumb trails include the current page as plain text rather than as a link. This avoids adding a redundant link and tab stop for the current location.

  • All ancestor items are links to their corresponding locations. (2.4.4, 4.1.2)
  • The current page appears as the final item in the breadcrumb trail and is distinguishable from linked ancestor items. (1.3.1, 1.4.1)
  • When the current page is presented as non-link text, aria-current="page" is optional but may provide additional programmatic context. (1.3.1, 4.1.2)

Responsive and truncated breadcrumbs

Responsive breadcrumbs may wrap, truncate labels, or provide an overflow mechanism when there is insufficient horizontal space to show every item.

  • All breadcrumb destinations remain available through a keyboard-operable interaction. (2.1.1)
  • Truncated text does not make a link's destination ambiguous. The accessible name provides the full destination name when necessary. (2.4.4, 4.1.2)
  • An overflow control has an accessible name that identifies its purpose, such as "Show 3 hidden breadcrumb items." (2.4.6, 4.1.2)
  • The overflow mechanism has appropriate semantics and keyboard behavior for its implemented pattern. (2.1.1, 4.1.2)
  • Wrapping, truncation, or overflow behavior does not require two-dimensional page scrolling at narrow widths or high zoom. (1.4.10)

Best practices

These practices improve usability and robustness, although not all are separate WCAG requirements in every implementation.

  • Place breadcrumbs consistently near the beginning of the main content, typically after the site header and before the page heading.
  • Use a navigation landmark with an accessible name such as Breadcrumb or Breadcrumb navigation.
  • Use an ordered list to represent the hierarchy from the highest-level ancestor to the current page.
  • Use concise labels that match or closely correspond to the titles of the linked pages or sections.
  • Ensure the sequence reflects the site's hierarchy rather than simply a user's browsing history.
  • Include the current page as the final item when doing so helps users understand their location.
  • Choose one consistent current-page treatment: present it as non-link text, or retain it as a link marked with aria-current="page".
  • Generate decorative separators with CSS where possible. If they are in the DOM, hide them from assistive technology.
  • Use CSS-generated or otherwise hidden decorative separators when the ordered-list and navigation semantics already convey the breadcrumb relationship.
  • Allow breadcrumb items to wrap at narrow widths rather than clipping them or forcing horizontal page scrolling.
  • Do not truncate a breadcrumb label in a way that makes the linked destination unclear. Provide an accessible full name when visual truncation is unavoidable.
  • When the hierarchy is very deep, provide a usable responsive treatment, such as wrapping or a clearly labeled overflow pattern, rather than hiding intermediate levels without an accessible method to access them.
  • Use a visible current-page treatment in addition to any programmatic indication, such as plain text, font treatment, or a non-color distinction.
  • Do not use title attributes as the sole method of providing a full breadcrumb label or destination name.

Practical test sequence

Focus Details Applicable Criteria
Identify function
  • Confirm that the component is a breadcrumb trail and that it communicates hierarchical location or navigation to ancestor pages or sections. (1.3.1)
  • Confirm that the component is not primary navigation, a back link, pagination, a progress indicator, or a history trail with a different purpose.
  • Determine whether the trail includes the current page and whether the current-page item is a link or plain text.
  • Determine whether the breadcrumbs can wrap, truncate items, or use an overflow control at narrow widths.
  • WCAG 2.2: Understanding SC 1.3.1 Info and Relationships (Level A)
Semantics and language
  • Confirm that the breadcrumb trail is contained in a <nav> landmark or an equivalent navigation region with an accessible name such as "Breadcrumb". (1.3.1, 4.1.2)
  • Confirm that the trail uses an ordered list or another programmatically determinable structure that communicates the hierarchy. (1.3.1)
  • Confirm that each ancestor item is a native <a> element with an href, where feasible. (4.1.2)
  • Confirm that each link has a meaningful accessible name and that the visible link text is included in the accessible name. (2.4.4, 2.5.3, 4.1.2)
  • Confirm that the sequence represents the correct hierarchy from ancestor to current location. (1.3.1)
  • If the current page is a link, confirm it exposes aria-current="page". (1.3.1, 4.1.2)
  • Confirm that decorative separators are hidden from assistive technology. Confirm that the breadcrumb navigation landmark and ordered-list structure convey the trail's purpose and sequence. (1.1.1, 1.3.1)
  • WCAG 2.2: Understanding SC 1.1.1 Non-text Content (Level A)
  • WCAG 2.2: Understanding SC 1.3.1 Info and Relationships (Level A)

  • WCAG 2.2: Understanding SC 2.5.3 Label in Name (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Screen reader
  • Confirm that the breadcrumb navigation landmark is announced with its accessible name. (1.3.1, 4.1.2)
  • Confirm that each ancestor item is announced as a link with a meaningful name. (2.4.4, 4.1.2)
  • Confirm that the current page is identified as current when it is a link. (1.3.1, 4.1.2)
  • If the current page is plain text, confirm that it is available in the expected final position and distinguishable from the links. (1.3.1)
  • Confirm that decorative separators do not create confusing, redundant, or excessively verbose announcements. (1.3.1)
  • Use a screen-reader links list or links navigation feature, where available, and confirm that breadcrumb link names remain understandable out of context. (2.4.4)
  • For truncated items, confirm that the accessible name communicates the full destination when needed. (2.4.4, 4.1.2)

  • WCAG 2.2: Understanding SC 2.4.4 Link Purpose (In Context) (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Keyboard only
  • Use Tab and Shift+Tab to move to and away from each breadcrumb link. Confirm that links appear in the same logical order as the displayed hierarchy. (2.1.1, 2.1.2, 2.4.3)
  • Confirm that each breadcrumb link has a visible focus indicator and is not completely hidden by sticky headers, banners, dialogs, or other author-created content. (2.4.7, 2.4.11)
  • Activate each breadcrumb link with Enter and confirm that it reaches the expected parent page or section. (2.1.1, 2.4.4)
  • Confirm that breadcrumb links do not activate merely because they receive focus. (3.2.1)
  • For an overflow mechanism, confirm that the control is keyboard-operable, opens predictably, and allows users to reach hidden breadcrumb destinations. (2.1.1, 2.4.3)

  • WCAG 2.2: Understanding SC 2.4.3 Focus Order (Level A)
  • WCAG 2.2: Understanding SC 2.4.4 Link Purpose (In Context) (Level A)
  • WCAG 2.2: Understanding SC 2.4.7 Focus Visible (Level AA)
  • WCAG 2.2: Understanding SC 2.4.11 Focus Not Obscured (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 3.2.1 On Focus (Level A)
Hierarchy and destinations
  • Compare the breadcrumb sequence against the site's information architecture and confirm that each item represents the correct ancestor page or section. (1.3.1)
  • Activate each ancestor link and confirm that it reaches the destination identified by the link text. (2.4.4)
  • Confirm that the final item correctly represents the current page or current location. (1.3.1)
  • Confirm that the current-page treatment is consistent across comparable pages. (3.2.4)
  • For responsive overflow behavior, confirm that intermediate ancestor destinations remain available rather than being permanently removed. (2.1.1, 2.4.4)
  • Navigate to comparable pages within the same set and confirm that the breadcrumb navigation occurs in the same relative order, with the same ancestor-to-current-page direction, each time it is repeated. (3.2.3)

  • WCAG 2.2: Understanding SC 3.2.4 Consistent Identification (Level AA)
Inspect visual aspects
  • Confirm that breadcrumb links are distinguishable from surrounding non-link text without relying on color alone. (1.4.1)
  • Check contrast for breadcrumb-link text in default, hover, active, visited, and focus states. (1.4.3)
  • Check contrast for separators, current-page indicators, overflow controls, icons, and focus indicators when they are needed to identify or operate the breadcrumb trail. (1.4.11)
  • Confirm that the current page is visually distinguishable from linked ancestor items without relying on color alone. (1.4.1)
  • Check 200% text resize, a 320-CSS-pixel-wide viewport, and text-spacing overrides. Breadcrumb labels, links, separators, and overflow controls must remain visible, identifiable, and operable without clipping, overlap, or unnecessary horizontal scrolling. (1.4.4, 1.4.10, 1.4.12)
  • For standalone breadcrumb links or an overflow control, confirm that the target meets the minimum target size or an applicable exception applies. Inline breadcrumb links whose size is constrained by surrounding text may qualify for the inline exception. (2.5.8)
  • Confirm that focused breadcrumb links and controls are visible against surrounding colors and are not completely hidden by other content. (1.4.11, 2.4.11)
