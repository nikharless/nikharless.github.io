Links

A link is an interactive element that navigates a user to another page, a location within the current page, a file, an email address, a telephone number, or another URL-addressable resource.

Links differ from buttons:

  • Use a link when activation navigates to another location or resource.
  • Use a button when activation performs an action within the current page or application, such as opening a dialog, submitting a form, revealing content, or changing a setting.
  • Use a native <a> element with a valid href whenever possible.
  • Do not use a link with href="#" or javascript: to perform an action that should be implemented as a button.

WCAG requirements

  • Each link has a programmatically determinable accessible name. (4.1.2)
  • The link purpose can be determined from its text alone or from its text together with programmatically determinable context, except where the purpose would be ambiguous to users in general. (2.4.4)
  • The link exposes link semantics. A native <a> element with an href provides link semantics automatically. (4.1.2)
  • The link is operable using a keyboard. A native link can be activated with Enter. (2.1.1)
  • The link has a visible focus indicator when it receives keyboard focus. (2.4.7)
  • Links appear in a logical focus order. (2.4.3)
  • Focused links are not completely hidden by sticky headers, banners, dialogs, or other author-created content. (2.4.11)
  • Links are visually distinguishable from surrounding non-link text without relying on color alone. (1.4.1)
  • Link text has sufficient contrast against its background. (1.4.3)
  • Link indicators, icons, and focus indicators that are needed to identify or operate links have sufficient non-text contrast. (1.4.11)
  • Visible link text is included in the accessible name. (2.5.3)
  • Links remain visible, identifiable, and operable at 200% text resize, at a 320-CSS-pixel-wide viewport, and when text-spacing overrides are applied. (1.4.4, 1.4.10, 1.4.12)
  • Links meet the minimum target-size requirement or an applicable exception applies. (2.5.8)
  • A link does not cause an unexpected change of context when it receives focus. (3.2.1)
  • Link labels, destinations, and behavior are identified consistently when the same function appears across multiple pages. (3.2.4)
  • Meaningful images used as the only content of a link have text alternatives that identify the link destination or purpose. (1.1.1, 2.4.4)

Best practices

These practices improve usability and robustness, although not all are separate WCAG requirements in every implementation.

  • Use specific, action-oriented link text, such as Download the 2026 annual report (PDF), rather than Click here or Read more.
  • Make the link text meaningful when read out of context whenever practical, even though WCAG 2.4.4 allows programmatically determinable context.
  • Use the same link text for the same destination whenever possible.
  • Do not give different destinations the same accessible name when they appear in the same context.
  • Do not rely solely on a title attribute to provide the link's accessible name or destination information.
  • Use text in addition to an icon when the icon's meaning may be unclear.
  • For an icon-only link, provide an accessible name that describes the destination or action, and hide a decorative icon from assistive technology.
  • Ensure the entire visible link area is clickable, rather than only a small part of an icon or text treatment.
  • Use a visible visited-link style when it is useful for users to distinguish previously visited content.
  • Do not use a link styled as a button when it performs an in-page action.
  • Do not use a button styled as a link when it navigates to another page or resource.
  • Do not remove link underlines unless another non-color visual distinction remains available in all relevant states.
  • Use a descriptive file type and size for links that download substantial documents or media when practical.
  • Warn users when a link opens a new browser tab, window, or external application, unless the behavior is clearly expected.
  • Use an appropriate in-page target and move focus to it when an in-page link changes the user's current reading location.

In-page and skip links

An in-page link moves a user to another location within the same page. A skip link is an in-page link that allows users to bypass repeated page content, such as a site header or navigation menu.

  • The link destination exists and is programmatically focusable when keyboard focus needs to move to it. (2.4.1, 2.4.3)
  • Activating the in-page link moves focus to the destination or otherwise preserves a meaningful keyboard location. (2.4.3)
  • Skip links allow users to bypass repeated blocks of content. (2.4.1)
  • The target is not completely obscured by sticky headers or other author-created content after the link is activated. (2.4.11)
  • The destination is identified with a meaningful heading, landmark, or other appropriate structure. (1.3.1, 2.4.6)

Links that open new contexts

A link may open a new browser tab, a new window, a separate application, an email client, a telephone application, or another context. The change should be understandable before users activate the link when it would be unexpected.

  • The link purpose identifies the result or destination. (2.4.4)
  • The link does not open a new window, tab, or other context merely because it receives focus. (3.2.1)
  • If a link opens a new browser context unexpectedly, users are informed before activation through link text, associated text, or another accessible indication. (3.2.2)
  • A link that opens a file, email client, telephone application, or external application identifies that result when the result would otherwise be unclear. (2.4.4, 3.2.2)
  • If an icon is used to communicate that a link opens a new window or external site, the information is available to assistive technology. (1.1.1, 4.1.2)

Image and icon links

An image link is a link whose content is an image, icon, logo, or other non-text graphic. Its accessible name should describe the link destination or purpose, not merely the image's appearance.

  • An image-only link has text alternative that identifies the link's destination or purpose. (1.1.1, 2.4.4)
  • Decorative images inside a text link are hidden from assistive technology. (1.1.1)
  • An icon-only link has an accessible name independent of the icon's visual appearance. (4.1.2)
  • When a visible text label accompanies an icon, the visible label is included in the link's accessible name. (2.5.3)
  • The image or icon is sufficiently distinguishable when it is needed to identify the link or its destination. (1.4.11)

Practical test sequence

Focus Details Applicable Criteria
Semantics and language
  • Confirm that the element is a link because activation navigates to a location or resource, rather than performing an in-page action. (1.3.1, 4.1.2)
  • Confirm that the link uses a native <a> element with an href, where feasible. (4.1.2)
  • Confirm that the link has a meaningful accessible name. (4.1.2)
  • Confirm that the purpose of the link can be determined from the link text alone or from its link text and programmatically determinable context. (2.4.4)
  • Confirm that visible link text is included in the accessible name. (2.5.3)
  • When multiple links have the same name in the same context, confirm that they lead to the same or equivalent destinations. (2.4.4)
  • Confirm that links with the same purpose are identified consistently across pages. (3.2.4)

  • WCAG 2.2: Understanding SC 2.5.3 Label in Name (Level A)
  • WCAG 2.2: Understanding SC 3.2.4 Consistent Identification (Level AA)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Screen reader
  • Confirm that the element is announced as a link. (4.1.2)
  • Verify the accessible name and confirm that it identifies the link purpose or destination. (2.4.4, 4.1.2)
  • Use a links list or other screen-reader link navigation feature, where available, and confirm that link names remain understandable. (2.4.4)
  • Confirm that visible link text is included in the announced name. (2.5.3)
  • Confirm that decorative icons and images are not announced unnecessarily. (1.1.1)
  • For image-only or icon-only links, confirm that the announced name describes the destination or purpose rather than the image's appearance. (1.1.1, 2.4.4)
  • For links that open a new window, download a file, or launch another application, confirm that the relevant behavior is available to assistive technology when it is not obvious from the link name. (1.1.1, 2.4.4)

  • WCAG 2.2: Understanding SC 2.4.4 Link Purpose (In Context) (Level A)
  • WCAG 2.2: Understanding SC 2.5.3 Label in Name (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Keyboard only
  • Use Tab and Shift+Tab to reach and move away from each link. Confirm that links appear in a logical focus order. (2.1.1, 2.4.3)
  • Confirm that each link has a visible focus indicator and that the focused link is not completely hidden by sticky headers, banners, dialogs, or other author-created content. (2.4.7, 2.4.11)
  • Activate each link with Enter. Confirm that keyboard activation produces the same result as pointer activation. (2.1.1)
  • Confirm that the link does not activate merely because it receives focus. (3.2.1)
  • Confirm that custom links, if present, can be reached with Tab and activated with Enter. (2.1.1, 4.1.2)
  • For in-page links, confirm that focus moves to the destination and that the new location is not obscured. (2.4.1, 2.4.3, 2.4.11)
  • For skip links, confirm that activation bypasses repeated content and moves focus to the beginning of the main content or another appropriate destination. (2.4.1, 2.4.3)

  • WCAG 2.2: Understanding SC 2.4.3 Focus Order (Level A)
  • WCAG 2.2: Understanding SC 2.4.7 Focus Visible (Level AA)
  • WCAG 2.2: Understanding SC 2.4.11 Focus Not Obscured (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 3.2.1 On Focus (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Destinations and behavior
  • Activate the link and confirm that it reaches the expected destination, resource, file, application, or in-page target. (2.4.4)
  • Confirm that the destination corresponds to the link's visible text and accessible name. (2.4.4)
  • For links that open a new tab, window, email client, telephone application, external application, or file download, confirm that the resulting behavior is understandable before activation when it would otherwise be unexpected. (2.4.4, 3.2.2)
  • Confirm that a link does not unexpectedly open a new window, tab, or application because it receives focus. (3.2.1)
  • For links that download files, confirm that file type and other useful information are provided when needed to understand the result. (2.4.4)
  • For in-page links, confirm that the destination exists, is meaningful, and can receive focus where focus movement is required. (1.3.1, 2.4.3)

  • WCAG 2.2: Understanding SC 3.2.2 On Input (Level A)
Inspect visual aspects
  • Confirm that links are distinguishable from surrounding non-link text without relying on color alone. (1.4.1)
  • Check link-text contrast in default, visited, hover, active, and focus states. (1.4.3)
  • Check contrast for link icons, external-link indicators, underlines, and focus indicators when those indicators are necessary to identify or operate the link. (1.4.11)
  • Check 200% text resize, a 320-CSS-pixel-wide viewport, and text-spacing overrides. Links must remain visible, identifiable, and operable without clipping, overlap, or unnecessary horizontal scrolling. (1.4.4, 1.4.10, 1.4.12)
  • Confirm that each link meets the minimum target size or has sufficient spacing from adjacent targets. (2.5.8)
  • Confirm that icon-only links have a visible indication of their purpose where needed and an adequate activation area. (1.4.11, 2.5.8)
