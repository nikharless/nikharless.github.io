Accordions

An accordion is a vertically stacked set of interactive headings that expand and collapse to reveal or hide associated panels of content.

WCAG Requirements

  • Each accordion heading has a role of button.
  • Each accordion header button is inside a heading of the correct level. No other elements are within the heading.
  • The header button has aria-expanded="false" when the panel is not visible, and aria-expanded="true" when the panel is visible.
  • The header button has aria-controls set to the id of the panel element.

Practical Test Sequence

Focus Details Applicable Criteria
Semantics and language
  • Confirm each visible accordion label has an appropriate heading structure where it functions as a page section heading.
  • Confirm the activation control is a native <button>, where feasible, or has role="button".
  • Confirm headings describe the section's topic or purpose.
  • If the accordions appear across multiple pages, confirm that they are identified consistently.
  • WCAG 2.2: Understanding SC 1.3.1 Info and Relationships (Level A)
  • WCAG 2.2: Understanding SC 2.4.6 Headings and Labels (Level AA)
  • WCAG 2.2: Understanding SC 3.2.4 Consistent Identification (Level AA)
Screen reader
  • With a screen reader or accessibility tree, verify a meaningful name, button role, and correct collapsed/expanded state.
  • Expand and collapse each header and confirm the state updates.
  • WCAG 2.2: Understanding SC 1.3.2 Meaningful Sequence (Level A) (content remains ordered when expanded)
  • WCAG 2.2: Understanding SC 2.5.3 Label in Name (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A) (role, name, expanded state)
  • WCAG 2.2: Understanding SC 4.1.3 Status Messages (Level AA)
Keyboard only Use Tab, Shift+Tab, Enter, and Space. Verify every header expands/collapses with both Enter and Space, focus remains visible, revealed interactive content becomes reachable, and collapsed content does not retain keyboard focusability. When a panel is collapsed, ensure its visual content is not exposed as active keyboard stops. When expanded, ensure content is actually rendered/exposed appropriately and follows its trigger logically. Test especially when focus is in the panel and the panel is then collapsed through scripting or another control.
  • WCAG 2.2: Understanding SC 2.1.1 Keyboard (Level A) (Tab navigation and Enter and Space activation required)
  • WCAG 2.2: Understanding SC 2.1.2 No Keyboard Trap (Level A)
  • WCAG 2.2: Understanding SC 2.1.4 Character Key Shortcuts (Level A)
  • WCAG 2.2: Understanding SC 2.4.3 Focus Order (Level A) (focus lost or moved on activation, skips revealed controls, goes to collapsed content)
  • WCAG 2.2: Understanding SC 2.4.7 Focus Visible (Level AA)
  • WCAG 2.2: Understanding SC 2.4.11 Focus Not Obscured (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 3.2.1 On Focus (Level A) (tabbing to header automatically expands it)
  • WCAG 2.2: Understanding SC 3.2.2 On Input (Level A)
Inspect visual aspects Check contrast, 200% text resize, 400% browser zoom/reflow, text spacing overrides, and narrow viewports. Inspect whether long labels wrap rather than clip and whether the full header remains an adequately sized target.
  • WCAG 2.2: Understanding SC 1.3.3 Sensory Characteristics (Level A) ("select the arrow on the right...")
  • WCAG 2.2: Understanding SC 1.4.3 Contrast (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 1.4.4 Resize Text (Level AA)
  • WCAG 2.2: Understanding SC 1.4.10 Reflow (Level AA)
  • WCAG 2.2: Understanding SC 1.4.11 Non-text Contrast (Level AA) (outline, icon, focus boundary)
  • WCAG 2.2: Understanding SC 1.4.12 Text Spacing (Level AA)
  • WCAG 2.2: Understanding SC 2.5.8 Target Size (Minimum) (Level AA)
