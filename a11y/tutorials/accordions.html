Accordions

An accordion is a vertically stacked set of interactive headings that expand and collapse to reveal or hide associated panels of content.

WCAG requirements

  • Each accordion heading has a role of button. (4.1.2)
  • Each accordion header button is inside a heading of the correct level. No other elements are within the heading. (1.3.1)
  • The header button has aria-expanded="false" when the panel is not visible, and aria-expanded="true" when the panel is visible. (4.1.2)
  • The header button has aria-controls set to the id of the panel element. (4.1.2)

Best practices

These practices improve usability and robustness, although not all are separate WCAG requirements in every implementation.

  • Each header button has a visual indicator of its expanded state (e.g., a chevron).
  • Do not auto-collapse other panels. This can disorient low-vision users using high zoom levels or screen magnifiers.
  • Ensure that opening an accordion panel does not push the header out of the viewport, so users don't have to scroll to get back to it.
  • Make the entire header region of the accordion row clickable, not just the text label or icon.
  • Auto-expand all accordion panels when a user prints the web page using CSS media queries.
  • Allow Up Arrow and Down Arrow to navigate between accordion headers.

Practical test sequence

Focus Details Applicable Criteria
Semantics and language
  • Confirm each visible accordion label has an appropriate heading structure where it functions as a page section heading. (1.3.1)
  • Confirm the activation control is a native <button>, where feasible, or has role="button". (4.1.2)
  • Confirm headings describe the section's topic or purpose. (2.4.6)
  • If the accordions appear across multiple pages, confirm that they are identified consistently. (3.2.4)
  • WCAG 2.2: Understanding SC 1.3.1 Info and Relationships (Level A)
  • WCAG 2.2: Understanding SC 2.4.6 Headings and Labels (Level AA)
  • WCAG 2.2: Understanding SC 3.2.4 Consistent Identification (Level AA)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Screen reader
  • Confirm the activation control is identified as a button. (4.1.2)
  • Verify a meaningful name. Visible labels must be included in the accessible name. Decorative icons should not be read. (4.1.2, 2.5.3, 1.1.1)
  • Verify the expanded state is communicated on focus. (4.1.2)
  • Expand and collapse each header and confirm the correct state is announced. (4.1.2)
  • Confirm content is read in a meaningful order when expanded. (1.3.2)
  • WCAG 2.2: Understanding SC 1.1.1 Non-text Content
  • WCAG 2.2: Understanding SC 1.3.2 Meaningful Sequence (Level A)
  • WCAG 2.2: Understanding SC 2.5.3 Label in Name (Level A)
  • WCAG 2.2: Understanding SC 4.1.2 Name, Role, Value (Level A)
Keyboard only
  • Use Tab and Shift+Tab to focus and unfocus each header. Use Enter and Space to expand them. Keyboard activation should perform the same function as a mouse click. The page should not scroll unexpectedly when Space is used to activate the button. Disabled buttons should not be activatable. (2.1.1, 2.1.2)
  • Confirm that each header control and any interactive controls inside the expanded content have a visible focus indicator. Verify that focusable headers and controls inside sections are not completely hidden by other content. (2.4.7, 2.4.11)
  • Confirm that the headers and expanded content sections appear in a logical focus order. When a section is collapsed, ensure its content does not gain keyboard focus. Verify appropriate focus order when focus is inside the panel and the panel is then collapsed through scripting or another control. (2.4.3)
  • Confirm that the section does not automatically expand on focus. (3.2.1)
  • WCAG 2.2: Understanding SC 2.1.1 Keyboard (Level A)
  • WCAG 2.2: Understanding SC 2.1.2 No Keyboard Trap (Level A)
  • WCAG 2.2: Understanding SC 2.4.3 Focus Order (Level A)
  • WCAG 2.2: Understanding SC 2.4.7 Focus Visible (Level AA)
  • WCAG 2.2: Understanding SC 2.4.11 Focus Not Obscured (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 3.2.1 On Focus (Level A)
Inspect visual aspects
  • Check contrast for text and icons in all states (focus, active, expanded/collapsed). Check contrast for the focus indicator. (1.4.3, 1.4.11)
  • Confirm expanded state is not conveyed by color alone. (1.4.1)
  • Check 200% text resize, 320-CSS-pixel-wide viewport, and text spacing overides. The header controls and section content must remain visible, unclipped, unobscured, and usable. Horizontal scrolling should not be required. (1.4.4, 1.4.10, 1.4.12)
  • Confirm target size or sufficient spacing. (2.5.8)
  • WCAG 2.2: Understanding SC 1.4.3 Contrast (Minimum) (Level AA)
  • WCAG 2.2: Understanding SC 1.4.4 Resize Text (Level AA)
  • WCAG 2.2: Understanding SC 1.4.10 Reflow (Level AA)
  • WCAG 2.2: Understanding SC 1.4.11 Non-text Contrast (Level AA)
  • WCAG 2.2: Understanding SC 1.4.12 Text Spacing (Level AA)
