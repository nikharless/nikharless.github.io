Charts and graphs

A chart or graph is a visual representation of data, relationships, trends, comparisons, distributions, or processes. Examples include bar charts, line charts, pie charts, scatterplots, heat maps, maps, timelines, dashboards, and data-driven diagrams.

Charts and graphs differ from related content:

  • Use a chart or graph when a visual representation helps users understand patterns, comparisons, trends, distributions, or relationships in data.
  • Use a data table when users need to locate, compare, or copy exact values.
  • Provide both a visual chart and an accessible text alternative or data-table equivalent when the chart conveys information needed to understand the content.
  • Use a static image chart only when it does not need keyboard interaction, filtering, drill-down, tooltips, zoom, or other dynamic behavior.
  • Use an interactive chart only when its interactive features provide meaningful value beyond a static chart and accessible data alternative.
  • Do not use a chart as the only way to present information users need to understand, compare, act on, or make a decision.

WCAG requirements

  • Each informative chart or graph has a text alternative that serves the equivalent purpose and conveys the essential information available visually. (1.1.1)
  • Complex charts and graphs have a long description, nearby explanatory text, accessible data table, or another text-based alternative that communicates the essential data, trends, relationships, comparisons, outliers, and conclusions conveyed visually. (1.1.1)
  • The chart has a meaningful title, caption, heading, or accessible name that identifies its topic, data subject, and purpose. (1.3.1, 2.4.6, 4.1.2)
  • Axis titles, units, data-series names, legends, labels, annotations, and other information needed to interpret the chart are available in text. (1.3.1, 1.1.1)
  • Data categories, series, values, and relationships are not conveyed by color alone. (1.4.1)
  • Text in charts, including titles, axis labels, legends, annotations, and data labels, has sufficient contrast against its background. (1.4.3)
  • Meaningful graphical objects, data marks, lines, boundaries, and state indicators have sufficient non-text contrast when contrast is needed to understand the chart. (1.4.11)
  • The chart remains understandable and usable when text is enlarged, spacing is increased, or the viewport is narrow. (1.4.4, 1.4.10, 1.4.12)
  • Interactive chart controls and functions exposed to keyboard or assistive-technology users are operable with a keyboard. (2.1.1)
  • A visual-only interactive chart or map may be removed from the accessibility tree and keyboard sequence when an equivalent accessible interface provides the same functionality and essential information. (1.1.1, 2.1.1)
  • If a chart includes keyboard-focusable data points, controls, legend items, annotations, or other interactive objects, they appear in a logical focus order. (2.4.3)
  • Keyboard focus is visible on interactive chart elements and is not completely hidden by other content. (2.4.7, 2.4.11)
  • Interactive chart controls and elements have programmatically determinable names, roles, states, values, and relevant relationships. (1.3.1, 4.1.2)
  • Interactive chart information that appears on hover is also available when the relevant element receives keyboard focus, when the information is needed to understand or operate the chart. (1.4.13, 2.1.1)
  • Content that appears on hover or focus is dismissible, hoverable, and persistent when WCAG 1.4.13 applies. (1.4.13)
  • Dynamic chart updates, filtering results, loading states, errors, and selected data states are programmatically determinable and communicated to assistive technology when users need that information. (4.1.2, 4.1.3)
  • Chart controls, data filters, legends used as controls, zoom controls, reset controls, download controls, and other pointer targets meet the minimum target-size requirement or an applicable exception applies. (2.5.8)
  • Changing chart filters, selecting a data point, moving focus through a chart, or using chart controls does not cause an unexpected change of context. (3.2.1, 3.2.2)

Static charts and graphs

A static chart is a non-interactive chart, graph, map, diagram, or data visualization. It may be an image, SVG, PDF-derived graphic, or another non-interactive visual representation.

  • The chart has a short text alternative that identifies the chart type, topic, and purpose. (1.1.1)
  • A complex chart has a longer text alternative that conveys the essential trends, comparisons, data relationships, and conclusions available from the visual. (1.1.1)
  • When exact values are important, an accessible data table or equivalent text-based presentation is available. (1.1.1)
  • The chart title, caption, legend, axes, units, and annotations are available in text. (1.3.1, 1.1.1)
  • Data series and categories can be distinguished without relying on color alone. (1.4.1)
  • Text and meaningful graphical objects have sufficient contrast. (1.4.3, 1.4.11)

Interactive charts and graphs

An interactive chart allows users to filter data, select data points, reveal tooltips, drill down into data, zoom, pan, hide or show series, change the chart type, or download data.

  • Every interactive function exposed to keyboard or assistive-technology users is keyboard-operable. (2.1.1)
  • When a chart's visual interactive layer is hidden from assistive technology and keyboard navigation, an equivalent accessible interface provides the same functions, data, selected state, and resulting content. (1.1.1, 2.1.1, 4.1.2)
  • Interactive controls have accessible names, appropriate roles, and programmatically determinable states and values. (4.1.2)
  • Data-point information needed to understand the chart is available through keyboard focus or another accessible method. (1.1.1, 2.1.1, 4.1.2)
  • Hover-only information is available on keyboard focus when it is needed to understand or operate the chart. (1.4.13, 2.1.1)
  • Interactive tooltips and overlays are dismissible, hoverable, and persistent when they obscure or replace content and are triggered by hover or focus. (1.4.13)
  • Interactive data-point focus order is logical and does not create an excessive or impractical number of tab stops. (2.4.3)
  • Users can determine the selected point, active series, applied filter, zoom level, or other current chart state. (1.3.1, 4.1.2)
  • Filter changes, drill-down results, loading states, and errors are communicated when users need the information. (4.1.3)
  • Users can reset or reverse filters, zoom, panning, hidden-series settings, and other changed chart states. (2.1.1, 3.2.2)

Data tables and descriptions

A data table or long description provides an accessible non-visual equivalent for a chart. The alternative should support the chart's purpose, not merely repeat every decorative visual detail.

  • The text alternative identifies the chart type, topic, measure, units, time period, categories, and series needed to understand the visualization. (1.1.1, 1.3.1)
  • The description communicates the main patterns, comparisons, trends, peaks, lows, outliers, and conclusions conveyed visually. (1.1.1)
  • When exact values are important, an accessible table or equivalent text presentation provides those values. (1.1.1)
  • A data table has an appropriate caption, headers, scope, and structural relationships. (1.3.1)
  • If a table is hidden behind a control, the control has a meaningful accessible name and is keyboard-operable. (2.1.1, 4.1.2)
  • The relationship between the chart and its summary, long description, or data table is clear in the visual and reading order. (1.3.1, 1.3.2)

Maps and geographic charts

A map or geographic visualization uses spatial position, regions, symbols, color, or boundaries to communicate location-based data.

  • The map has a text alternative that communicates its topic, geographic scope, and essential information. (1.1.1)
  • Regions, markers, boundaries, and categories are not distinguished by color alone. (1.4.1)
  • A text-based alternative provides the essential location-based relationships, values, comparisons, and conclusions represented by the map. (1.1.1)
  • Interactive map controls, markers, regions, and popups that are exposed to keyboard or assistive-technology users are keyboard-operable and expose appropriate names, roles, states, and values. (2.1.1, 4.1.2)
  • A visual interactive map may be removed from the accessibility tree and keyboard sequence when an adjacent or otherwise available accessible interface provides equivalent location selection, information, states, and resulting content. (1.1.1, 2.1.1, 4.1.2)
  • Pan, zoom, drag, and other map interactions have alternatives that do not require dragging or complex pointer gestures when applicable. (2.5.1, 2.5.7)
  • When location information is essential, users can access it by search, list, table, text description, or another non-spatial method. (1.1.1)

Best practices

These practices improve usability and robustness, although not all are separate WCAG requirements in every implementation.

  • Start with the user question the chart is intended to answer, then provide a text summary that answers the same question.
  • Provide a concise chart title that states what is being compared or measured.
  • Provide a short summary near the chart describing the main takeaway, such as the overall trend, largest change, comparison, outlier, or conclusion.
  • Provide an accessible data table when users may need exact values, especially for charts with a manageable number of data points.
  • Use a visible View data table control when a table is not displayed by default.
  • Use clear axis labels that identify the measure, units, time period, and scale.
  • Use direct labels on data series when practical instead of requiring users to repeatedly match a series to a distant legend.
  • Use more than color to distinguish data series, such as patterns, line styles, point shapes, direct labels, texture, or data labels.
  • Avoid pie charts with many segments, 3D charts, distorted scales, truncated axes that exaggerate differences, and other visual treatments that make comparison difficult.
  • Do not rely solely on hover tooltips to convey exact values, series names, or key findings.
  • Provide keyboard-operable alternatives for all interactive functions, such as filtering, zooming, panning, selecting points, drilling down, and downloading data.
  • Keep keyboard focus manageable. Do not make hundreds of individual data points separate tab stops without an efficient navigation model or a data-table alternative.
  • Provide a visible reset control when users can filter, zoom, pan, hide series, or otherwise change the chart view.
  • Provide accessible download options, such as CSV, accessible HTML table, or a text summary, when users need the underlying data.
  • Use plain language in summaries and descriptions. Explain abbreviations, units, statistical terms, and domain-specific terminology when needed.
  • Test chart colors with color-vision simulation and contrast tools, but also test whether series remain distinguishable without color.
  • Keep the chart and its title, legend, description, filters, and data table close together in the reading order.
  • When using canvas, provide a complete accessible alternative because canvas pixels alone do not expose meaningful semantic information.
  • When a chart or map is a duplicate pointer-oriented visual enhancement, either make its interactive elements fully accessible or remove the visual layer from the accessibility tree and keyboard sequence while providing an equivalent accessible control, list, table, or text-based interface.
  • Do not expose a visual chart or map as interactive to screen-reader users if its points, regions, or controls cannot be reached and operated with the keyboard.

Practical test sequence

Focus Details Applicable Criteria
Identify function
  • Determine the chart's purpose: comparison, trend, distribution, composition, relationship, location, progress, status, or another data question. (1.1.1)
  • Identify every information source needed to interpret the chart, including title, caption, axes, units, legend, series labels, data labels, annotations, filters, tooltips, and data table. (1.3.1)
  • Determine whether the chart is static or interactive.
  • For an interactive chart, identify all supported functions, such as filtering, selecting, drill-down, zooming, panning, hover tooltips, hidden-series controls, reset controls, export, download, or accessible data views.
  • Determine whether the chart is implemented as an image, SVG, canvas, HTML, third-party widget, map, or another technology.
  • Determine whether the visual chart or map is the primary interactive interface or a duplicate visual enhancement paired with an equivalent accessible control, list, table, or text-based interface.

  • Apply filters, select data points, change chart settings, and load new data. Confirm that resulting status and data changes are announced when needed. (4.1.3)
  • For canvas-based charts, confirm that the complete essential information is available through an accessible text-based alternative. (1.1.1)

Keyboard only
  • For chart controls, points, regions, and other interactive elements exposed to keyboard users, use Tab and Shift+Tab to reach them and confirm that every exposed function is keyboard-operable. If a visual interactive layer is removed from keyboard navigation, confirm that an equivalent accessible interface provides the same functions and results. (2.1.1)
  • For a map with selectable regions or markers, confirm that users can select each available location through a keyboard-operable map interface or an equivalent accessible selector, list, search, or table. If the visual map is hidden from assistive technology, confirm that no map controls or regions remain focusable. (1.1.1, 2.1.1, 4.1.2)
  • Confirm that keyboard focus order is logical and that the chart does not create an excessive or unusable number of tab stops. (2.4.3)
  • Operate every interactive chart feature with the keyboard, including filters, selection, drill-down, series visibility, zoom, pan, reset, data table, and download features when present. (2.1.1)
  • Confirm that all focused chart controls and interactive objects have visible focus indicators and are not completely hidden by other content. (2.4.7, 2.4.11)
  • For keyboard-focusable data points, confirm that focus movement exposes useful data and does not activate a point or change the chart view unexpectedly. (3.2.1, 4.1.2)
  • For tooltips or overlays that appear on focus, confirm that users can dismiss them when required, and that they do not prevent access to the focused object or other necessary controls. (1.4.13)
  • Confirm that users can leave the chart and any opened overlays, menus, or popups using the keyboard without encountering a keyboard trap. (2.1.2)
  • Confirm that changing a filter, selecting a point, or activating a chart control does not unexpectedly submit a form, navigate away, or otherwise change context unless the behavior is clearly expected. (3.2.2)

Hover, touch, and pointer
  • Move the pointer over data points, series, legend items, regions, and annotations. Confirm that hover-only data needed to understand the chart is available through keyboard focus or another accessible method. (1.4.13, 2.1.1)
  • When a hover tooltip obscures or replaces other content, confirm that it can be dismissed without moving pointer hover or keyboard focus. (1.4.13)
  • Move the pointer from a trigger element to a hover tooltip and confirm that the tooltip remains visible long enough to read when users need to interact with or inspect it. (1.4.13)
  • If panning, zooming, selecting, or manipulating chart content requires dragging, confirm that users can complete the same function with a single pointer without dragging unless an exception applies. (2.5.7)
  • If chart interaction requires a path-based or multipoint gesture, confirm that users can complete the same function with a single pointer without a path-based gesture unless an exception applies. (2.5.1)
  • Confirm that interactive chart controls and data elements provide adequate pointer target size or spacing. (2.5.8)

Visual interpretation
  • Confirm that data series, categories, selected data, threshold lines, trend lines, positive/negative values, warnings, and other meaningful distinctions are not conveyed by color alone. (1.4.1)
  • Check contrast for chart text, axis labels, legends, data labels, annotations, and captions. (1.4.3)
  • Check contrast for meaningful chart lines, bars, points, segments, boundaries, icons, markers, selected states, hover states, and focus indicators. (1.4.11)
  • Confirm that patterns, labels, line styles, point shapes, direct labels, or another non-color method distinguish series and categories when needed. (1.4.1)
  • Confirm that chart text, axes, legends, annotations, and controls remain readable when text is resized to 200%. (1.4.4)
  • Check a 320-CSS-pixel-wide viewport and text-spacing overrides. Confirm that chart labels, controls, legends, descriptions, and data-table access remain visible and usable without unnecessary two-dimensional page scrolling. (1.4.10, 1.4.12)
  • Confirm that responsive chart behavior does not crop data, hide axis labels, overlap labels, or make essential information unavailable. (1.4.10)
